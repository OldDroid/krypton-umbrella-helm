krypton-umbrella

A Helm umbrella chart for Kubernetes/OpenShift, deployed by ArgoCD. One library chart drives naming, labels, merged annotations, dynamic sync waves and prune protection for every subchart — this page shows exactly which configuration produces which rendered manifest.

Dieses Helm-Umbrella-Chart bündelt Anwendungen für Kubernetes und OpenShift. Argo CD übernimmt die Bereitstellung. Die gemeinsame Library sorgt für einheitliche Namen, Labels, Annotations und Sync-Einstellungen. Die Beispiele zeigen, wie sich Values auf die erzeugten Manifeste auswirken.

Library validation: resource names longer than 63 characters or with an invalid format fail rendering. The combined partOfPrefix/laneName label must also fit within 63 characters. Existing configurations that relied on name truncation need an explicit migration. Decimal wave strings such as "08" mean 8; invalid integers and signed 64-bit overflow are rejected. Quote padded and very large numbers in YAML. The dedicated library references are in charts/krypton-lib/README.md and README.de.md.Library-Prüfungen: Ressourcennamen mit mehr als 63 Zeichen oder ungültigem Format führen zum Fehler. Das zusammengesetzte Label aus partOfPrefix/laneName darf ebenfalls höchstens 63 Zeichen lang sein. Bisher gekürzte Namen benötigen eine geplante Migration. Dezimale Wave-Strings wie "08" ergeben 8; ungültige Ganzzahlen und 64-Bit-Überläufe werden abgelehnt. Zahlen mit führenden Nullen und sehr große Zahlen in YAML als Strings angeben. Die eigenen Library-Referenzen stehen in charts/krypton-lib/README.md und README.de.md.

Overview

Überblick

Subcharts live as plain directories under charts/ and declare the library as a local dependency (file://../krypton-lib). When the umbrella renders, Helm loads every chart’s templates into one shared namespace, so the krypton-lib.* helpers resolve without vendoring.

Die Subcharts liegen unter charts/. Sie verwenden die gemeinsame Library krypton-lib. Beim Rendern des Umbrellas lädt Helm deren Helper zusammen mit den Subchart-Templates; eine zusätzliche Library-Kopie ist dafür nicht nötig.

Getting started

Einstieg

Run these commands from the repository root. Rendering produces YAML without installing it. Standalone subcharts need their library dependency built first. Gitignored library copies can still be loaded by Helm; remove stale copies before umbrella tests or use a fresh checkout.

Die Befehle gelten ab dem Stammverzeichnis dieses Repositorys. helm template erzeugt YAML, installiert aber nichts. Für ein einzelnes Subchart muss zuerst seine Library-Abhängigkeit gebaut werden. Erzeugte Library-Kopien können trotz .gitignore später von Helm geladen werden; vor Umbrella-Tests alte Kopien entfernen oder eine frische Arbeitskopie verwenden.

Resource naming & lanes

Ressourcennamen & Lanes

Every resource is named <subchart>-<laneName>[-<instance>]. The component type is deliberately not part of the name — the Kubernetes kind already tells the Deployment from the Service called krypton-banking-release; it is still passed to every helper because it selects the sync wave and prune protection. Several resources of one kind get an instance suffix, normalised to a DNS-1123 label. The lane is also stamped as app.kubernetes.io/part-of; an optional global.partOfPrefix prepends the umbrella name to that label (krypton-umbrella-release) without touching the names. The names get their own optional global.namePrefix: empty by default, acme renders acme-krypton-banking-release (shared resources included). Switching the lane renames everything consistently.

Eine Lane ist eine Umgebung wie release oder test. Namen folgen dem Schema [<namePrefix>-]<subchart>-<lane>[-<instance>]. Deployment und Service dürfen gleich heißen, weil ihre Ressourcentypen verschieden sind. Mehrere Ressourcen desselben Typs brauchen unterschiedliche Instanzen. Namen mit mehr als 63 Zeichen oder ungültigem Format führen zu einer Fehlermeldung. namePrefix betrifft Namen; partOfPrefix betrifft nur das Lane-Label. Ein Lane-Wechsel ändert nicht automatisch Ressourcenlimits oder Replikazahlen.

helm template krypton . --set global.laneName=test
Guard: an unset or empty global.laneName fails the render loudly — no lane-specific resource can ever be created without a lane in its name. Only resources explicitly marked shared (next card) drop it.Absicherung: ein fehlendes oder leeres global.laneName bricht das Rendern mit einer Fehlermeldung ab — keine Lane-spezifische Ressource entsteht je ohne Lane im Namen. Nur explizit als shared markierte Ressourcen (nächste Karte) lassen sie weg.

Shared resources without the lane

Geteilte Ressourcen ohne Lane

Shared objects omit the lane and must have exactly one managing Application per resource name. Consumers reference the same helper with chart: krypton-shared; this computes names but does not check readiness. The shared NetworkPolicy allows ingress from its own and selected ingress namespaces. It does not enforce Route-only access: permissions are additive and depend on network configuration. It does not restrict egress itself; other policies may.

krypton-shared erzeugt gemeinsam genutzte Objekte ohne Lane im Namen. Für jeden solchen Namen darf nur eine Application die Erzeugung übernehmen; der Schalter krypton-shared.enabled koordiniert das nicht automatisch. Konsumenten verwenden denselben Namens-Helper mit chart: krypton-shared. Die gemeinsame NetworkPolicy erlaubt Verkehr aus dem eigenen und ausgewählten Ingress-Namespaces. Sie garantiert keinen ausschließlich über Routes laufenden Zugang: Regeln sind additiv und von der Netzwerkkonfiguration abhängig. Diese Policy beschränkt Egress nicht; andere Policies können das tun.

helm template krypton .
helm template krypton-shared . -f values-shared-only.yaml
helm template krypton . --set krypton-shared.enabled=true
Ownership: one Application per namespace enables krypton-shared — the owning lane, or a dedicated shared Application via values-shared-only.yaml (see ArgoCD); every other lane keeps the default. Service-scoped sharing still exists: krypton-banking's config.shared renders its own ConfigMap as krypton-banking, gated by config.create. The slim umbrella has a similar shared subchart without NetworkPolicy (see the slim docs).Eigentümerschaft: eine Application pro Namespace aktiviert krypton-shared — die Eigentümer-Lane oder eine eigene shared-Application über values-shared-only.yaml (siehe ArgoCD); jede andere Lane behält den Default. Service-bezogenes Teilen gibt es weiterhin: config.shared von krypton-banking rendert dessen ConfigMap als krypton-banking, geschaltet über config.create. Slim bietet ein entsprechendes Shared-Subchart ohne NetworkPolicy (siehe Slim-Doku).

Labels & annotations merge

Labels- & Annotations-Merge

The metadata helper merges standard metadata and custom values. The three Pod identity labels are reserved and applied after custom labels. Annotations merge global values with per-call extras; configured Argo CD values take precedence. All resulting values are strings.

krypton-lib.metadata erzeugt Name, Labels und Annotations. Eigene Labels ergänzen die Standardwerte; die drei Identitätslabels für Pod-Selektoren bleiben reserviert. Annotations werden aus global.annotations und den Argumenten des Aufrufs zusammengeführt. Konfigurierte Argo-CD-Werte haben abschließend Vorrang. Alle resultierenden Werte werden als Strings ausgegeben.

Annotations for exactly one resource

Annotations für genau eine Ressource

global.annotations applies to every resource. For a single resource, use extra (a map), annotation (key=value), or annotationsFrom (a dotted values path). Missing paths contribute nothing; existing scalar targets fail. Only the Slim library supports a subchart-wide annotations map.

global.annotations gilt für jede Ressource. Für einzelne Ressourcen stehen extra (Map), annotation (ein String key=value) und annotationsFrom (Pfad unter .Values) bereit. Beispiel: route.annotations ergänzt nur die Route. Ein fehlender Pfad wird ignoriert; ein vorhandener skalarer Zielwert ist ein Fehler. Eine eigene Subchart-Ebene annotations bietet nur die Slim-Library.

helm template krypton . --set krypton-banking.route.annotations.haproxy\.router\.openshift\.io/timeout=300s
One mechanism, three spellings: extra/extraAnnotations is the dict form, annotation writes one entry of that dict inline, annotationsFrom looks the dict up in the values with nil-safe navigation and stringified values. Combined in one call they merge in exactly that order. The slim umbrella’s krypton-payments Route passes .Values.route.annotations as extraAnnotations — equivalent to annotationsFrom "route.annotations" as long as the path always exists.Ein Mechanismus, drei Schreibweisen: extra/extraAnnotations ist die Dict-Form, annotation schreibt einen Eintrag dieses Dicts inline, annotationsFrom schlägt das Dict nil-sicher in den Values nach und stringifiziert die Werte. In einem Aufruf kombiniert mergen sie genau in dieser Reihenfolge. Die krypton-payments-Route des schlanken Umbrellas reicht .Values.route.annotations als extraAnnotations durch — gleichwertig zu annotationsFrom "route.annotations", solange der Pfad immer existiert.

Pod selectors: Deployment ↔ Service

Pod-Selektoren: Deployment ↔ Service

Selectors use app.kubernetes.io/name, instance and part-of. The library protects these identity labels so Pod labels match. The release name defaults to the Argo CD Application name but helm.releaseName may override it. Deployment selectors are immutable; changing the lane label requires planned recreation.

Deployment- und Service-Selektoren verwenden die Labels app.kubernetes.io/name, app.kubernetes.io/instance und app.kubernetes.io/part-of. Die Library setzt diese Werte auch am Pod-Template und schützt sie vor Überschreiben. Der Release-Name ist standardmäßig der Argo-CD-Application-Name, kann aber mit helm.releaseName abweichen. Deployment-Selektoren sind unveränderlich; Änderungen am Lane-Label benötigen eine geplante Neuerstellung.

helm template krypton . --set global.partOfPrefix=krypton-umbrella
Selector changes: a Deployment selector is immutable. Renaming the lane creates a new Deployment anyway, but changing global.partOfPrefix on a lane that already runs changes only the selector and the apply is rejected — delete that lane's Deployments once, then sync again. Never add chart version or custom labels to the selector.Selektoränderungen: ein Deployment-Selektor ist unveränderlich. Eine Lane-Umbenennung erzeugt ohnehin ein neues Deployment, aber global.partOfPrefix auf einer bereits laufenden Lane zu ändern verändert nur den Selektor und der Apply wird abgelehnt — die Neuerstellung betroffener Deployments planen und mögliche Ausfallzeiten berücksichtigen. Nie Chart-Version oder eigene Labels in den Selektor aufnehmen.

ConfigMap delivery & pod restarts

ConfigMap-Zustellung & Pod-Neustarts

config.data supplies ConfigMap content. envFrom variables do not update in running containers, so rollPodsOnChange rolls Pods when config.data changes. A mountPath mounts a directory that updates asynchronously; the application must reload files itself. This checksum does not monitor external shared ConfigMaps or Secret updates.

config.data enthält den ConfigMap-Inhalt. envFrom importiert ihn als Umgebungsvariablen; diese ändern sich in laufenden Containern nicht. rollPodsOnChange löst deshalb bei Änderungen von config.data einen Rollout aus. Mit mountPath wird die ConfigMap als Verzeichnis eingebunden und zeitversetzt aktualisiert. Die Anwendung muss solche Dateien selbst neu einlesen. Externe Shared-ConfigMaps und Secret-Änderungen erfasst diese Prüfsumme nicht.

helm template krypton . --set krypton-banking.config.rollPodsOnChange=false --set krypton-banking.config.mountPath=/etc/krypton/config --set krypton-banking.config.envFrom=false

Sync waves: three-layer resolution

Sync-Waves: drei Auflösungsebenen

Subchart syncWaves values, including umbrella overrides, take precedence over global.syncWaves. Without a wave or offset, no wave annotation is generated. Zero and negative values are supported.

Für eine Komponente gilt zuerst syncWaves.<component> im Subchart einschließlich Umbrella-Overrides, danach global.syncWaves.<component>. Ohne Wave und ohne Offset wird keine Wave-Annotation erzeugt. Die Zahl 0 und negative Zahlen sind gültig; YAML-null ist kein Zahlenwert.

Cross-subchart ordering with syncWaveOffset

Subchart-übergreifende Reihenfolge mit syncWaveOffset

syncWaveOffset shifts every component wave, using zero for unconfigured waves. Choose offsets from actual ranges: local waves -9..9 need a step of at least 19; steps of ten overlap.

syncWaveOffset verschiebt alle Waves des Subcharts um denselben Wert. Eine nicht konfigurierte Wave zählt dafür als null. Die tatsächlichen Bereiche müssen getrennt bleiben: Für lokale Waves -9..9 sind mindestens 19 Abstand nötig; Zehnerschritte würden überlappen.

Implicit wave 0: with krypton-banking.syncWaveOffset=100, the HPA — which has no configured wave anywhere — renders sync-wave: "100" instead of escaping to wave 0. For local waves -9..9, use offset steps of at least 19 to avoid overlap.Implizite Wave 0: mit krypton-banking.syncWaveOffset=100 rendert der HPA — der nirgendwo eine Wave konfiguriert hat — sync-wave: "100", statt auf Wave 0 auszubrechen. Für lokale Waves -9..9 sind mindestens 19 Abstand nötig, damit sich die Bereiche nicht überlappen.

Per-component prune protection

Prune-Schutz je Komponente

syncPrune.<component>: false (same resolution chain as the waves) stamps Prune=false: the resource survives app-level pruning even when its manifest disappears or the subchart is disabled. Setting a key to true re-enables pruning over a global false.

syncPrune.<component>: false erzeugt Prune=false. Die Ressource bleibt dann beim Sync-Pruning erhalten, auch wenn ihr Manifest entfernt wird. true hebt einen geerbten Schutz auf. Das schützt nicht automatisch bei der kaskadierenden Löschung einer Application; Slim unterstützt dafür zusätzlich Delete=false.

Deploy switches per subchart

Deploy-Schalter je Subchart

Every application subchart hangs on a condition flag in the umbrella Chart.yaml. Disabling removes all of its manifests from the release; ArgoCD prunes the live resources — except those protected via syncPrune.

Ein condition-Eintrag in der Umbrella-Chart.yaml verbindet jedes Subchart mit seinem enabled-Schalter. Bei false werden seine Manifeste nicht mehr erzeugt. Wenn Pruning aktiviert ist, entfernt Argo CD die bisherigen Ressourcen mit Ausnahme geschützter Objekte.

helm template krypton . --set krypton-banking.enabled=false

Images & the per-lane registry switch

Images & der Registry-Schalter pro Lane

krypton-lib.image joins registry/repository:tag (a digest beats the tag). One umbrella key, global.imageRegistry, repoints every subchart at a proxy or air-gapped registry.

krypton-lib.image bildet registry/repository:tag. Ein Digest hat Vorrang vor dem Tag. global.imageRegistry überschreibt die Registry der Subcharts, die diesen Helper verwenden.

helm template krypton . --set global.imageRegistry=proxy.bank.internal:5000

Multiple VaultStaticSecrets, lane-aware paths

Mehrere VaultStaticSecrets, Lane-abhängige Pfade

Banking creates one VaultStaticSecret per vault.secrets entry. Its key supplies the name instance. Paths are evaluated with tpl; lane isolation depends on the configured path containing the lane. envFrom imports the operator-created destination Secret.

Banking erzeugt je Eintrag unter vault.secrets ein VaultStaticSecret. Der Schlüssel wird zur Instanz im Namen. Die Pfade werden mit tpl ausgewertet; nur wenn der konfigurierte Pfad die Lane enthält, sind die Pfade je Lane getrennt. envFrom: true importiert das vom Operator erzeugte Ziel-Secret.

ServiceAccount: created or referenced

ServiceAccount: erzeugt oder referenziert

Banking and Auth create ServiceAccounts by default. The base wave is -2; Auth adds its offset for wave 8. create: false references name, falling back to default. Configure VaultAuth for the account actually used.

Banking und Auth erstellen standardmäßig eigene ServiceAccounts. Die Basis-Wave ist -2; bei Auth kommt der Offset hinzu, also Wave 8. Mit serviceAccount.create: false und name wird ein vorhandener Account referenziert. Ohne Namen wird dann default verwendet. VaultAuth muss passend zum tatsächlich verwendeten Account konfiguriert sein.

helm template krypton . --set krypton-banking.serviceAccount.create=false --set krypton-banking.serviceAccount.name=legacy-vault-sa

Resources sized per lane

Resources pro Lane dimensioniert

Set resource requests and limits in each subchart block. Changing the lane name alone does not select different sizing. Use values files for environment-specific overrides.

Das Umbrella überschreibt Ressourcenanforderungen und Limits je Subchart. Die Lane-Bezeichnung allein wählt keine andere Dimensionierung. Eigene Values-Dateien können zum Beispiel für Testumgebungen kleinere Werte festlegen.

Optional components: PDB, HPA

Optionale Komponenten: PDB, HPA

Each follows the enabled-flag pattern and is steered per lane. While autoscaling.enabled is true, the Deployment stops rendering spec.replicas, so ArgoCD and the HPA never fight over the replica count. The namespace-wide NetworkPolicy is not a per-lane component — it is a shared resource of krypton-shared (see shared resources).

Banking unterstützt ein optionales PDB und einen HPA. Bei aktiviertem autoscaling entfällt die feste Replikazahl im Deployment. Die namespaceweite NetworkPolicy gehört zu krypton-shared und wird getrennt von den Lane-Komponenten verwaltet.

Rebranding the label domain

Label-Domain umbenennen

The generated label/annotation keys take their prefix from global.labelDomain, so the scaffold is reusable for other platforms with one values key — the library needs no edits.

global.labelDomain bestimmt das Präfix der erzeugten Annotation <domain>/source-chart. Eigene Schlüssel unter global.labels und global.annotations müssen bei einem Domain-Wechsel separat angepasst werden.

helm template krypton . --set global.labelDomain=acme.dev

Guardrails

Validierung

Schemas validate merged umbrella and application/shared-subchart values. Component helpers validate keys when rendering resources. Example charts also check resource-map names for collisions. Disabled charts do not run their template checks; rendering does not validate target-cluster prerequisites.

Schemas prüfen die zusammengeführten Values des Umbrellas und seiner Anwendungs-/Shared-Subcharts. Die Library prüft Komponenten-Keys, wenn sie Ressourcen rendert. Die Ressourcen-Maps der Beispielcharts werden zusätzlich auf gleiche fertige Namen geprüft. Das ersetzt keine Prüfung im Zielcluster; deaktivierte Charts führen ihre Template-Prüfungen nicht aus.

helm template krypton . --set krypton-banking.syncWaves.rout=9
helm template krypton . --set krypton-banking.syncWaves.route=abc
helm template krypton . --set krypton-banking.vault.secrets.app.pth=x
Deliberately tolerated: configuring a catalogued type that a subchart does not (yet) render is allowed and has no effect — waves and prune flags can be staged before the manifest exists.Bewusst toleriert: einen katalogisierten Typ zu konfigurieren, den ein Subchart (noch) nicht rendert, ist erlaubt und wirkungslos — Waves und Prune-Flags lassen sich vor dem Manifest anlegen.
GitOps

ArgoCD

Use chart path . for a lane Application. A separate Application can create shared objects using values-shared-only.yaml. Provision those objects before consumers; waves do not coordinate independent Applications.

Eine Application pro Lane verwendet den Chart-Pfad .. Sie kann vorhandene gemeinsame Objekte nutzen, während eine separate Application mit values-shared-only.yaml diese erzeugt. Gemeinsame Objekte müssen vor den Konsumenten verfügbar sein; Waves koordinieren keine unabhängigen Applications.
