Overview

Überblick

A second, self-contained umbrella next to the full one. Subcharts live under charts/ and declare krypton-lib-slim as a local dependency (file://../krypton-lib-slim); under the umbrella Helm loads every chart’s templates into one namespace, so the helpers resolve without vendoring. Pick this variant when the app teams own their manifests and the platform only needs consistent naming, labelling and ordering; pick the full umbrella when the platform should also standardise the workload spec. Both share the component catalog and the naming scheme, so the rendered names are identical.

Ein zweites, eigenständiges Umbrella neben dem vollen. Subcharts liegen unter charts/ und deklarieren krypton-lib-slim als lokale Abhängigkeit (file://../krypton-lib-slim); unter dem Umbrella lädt Helm die Templates aller Charts in einen Namensraum, die Helper sind also ohne Vendoring auflösbar. Diese Variante passt, wenn die App-Teams ihre Manifeste selbst besitzen und die Plattform nur konsistentes Naming, Labelling und Ordering braucht; das volle Umbrella passt, wenn die Plattform auch die Workload-Spec standardisieren soll. Beide teilen sich Komponentenkatalog und Namensschema, die gerenderten Namen sind identisch.

Seven helpers, one dict each: metadata (the whole block), componentName (names and cross-references), labels, selectorLabels, annotations, syncWave, syncOptions. ctx is always the caller’s root context — . in a template, $ or a saved $root inside a range. Arguments and values are listed in the reference.Sieben Helper, je ein Dict: metadata (der ganze Block), componentName (Namen und Querverweise), labels, selectorLabels, annotations, syncWave, syncOptions. ctx ist immer der Root-Kontext des Aufrufers — . im Template, $ oder ein gesichertes $root in einem range. Argumente und Values stehen in der Referenz.

Sync order at a glance

Sync-Reihenfolge auf einen Blick

ArgoCD applies resources wave by wave and waits for health in between. Waves resolve per component type (subchart value first, then global.syncWaves) and every instance of a type shares the wave: both VaultStaticSecrets of krypton-payments sync at -1, both Secrets and both ConfigMaps at 0. syncWaveOffset shifts a whole subchart’s band — krypton-notifier runs at offset +10, entirely after krypton-payments.

ArgoCD wendet Ressourcen Wave für Wave an und wartet dazwischen auf Health. Configuration examples

Konfigurationsbeispiele

Each card pairs a configuration with the manifest it renders. Every output block was captured verbatim from helm template krypton krypton-umbrella-slim (v4.2.4) — nothing is hand-written; # ... marks lines left out for brevity.

One include for the whole metadata block

Ein Include für den ganzen Metadata-Block

The core use-case. A manifest calls krypton-lib-slim.metadata once and receives name:, labels: and annotations:; everything else in the file is the subchart’s own YAML. The same names are reused for cross-references through componentName — the ServiceAccount the pod runs as, the ConfigMaps and Secrets it consumes — so a reference can never drift from the resource it points at.

Der Kern-Anwendungsfall. Ein Manifest ruft krypton-lib-slim.metadata einmal auf und bekommt name:, labels: und annotations:; alles andere in der Datei ist das eigene YAML des Subcharts. Dieselben Namen werden über componentName für Querverweise wiederverwendet — der ServiceAccount, unter dem der Pod läuft, die ConfigMaps und Secrets, die er konsumiert —, eine Referenz kann so nie von der Ressource abdriften, auf die sie zeigt.

Inside a range: the library needs the root context, not the loop item — pass $ (or a $root := . saved before the loop) as ctx, as the envFrom loops above do.In einem range: die Library braucht den Root-Kontext, nicht das Schleifenelement — $ (oder ein vor der Schleife gesichertes $root := .) als ctx übergeben, wie die envFrom-Schleifen oben.

Names, lanes & instance identifiers

Namen, Lanes & Instanz-Bezeichner

Every resource is named [<namePrefix>-]<subchart>-<laneName>[-<instance>]. The component type is not part of the name — the kind already tells the Deployment from the Service called krypton-payments-release. Several resources of one kind get an instance: krypton-payments renders its ConfigMaps, Secrets and VaultStaticSecrets from maps and uses the map key, normalised to a DNS-1123 label (camelCase boundaries become dashes, everything is lowercased, other characters become dashes). global.namePrefix prefixes every name, global.partOfPrefix prefixes only the app.kubernetes.io/part-of lane label. Switching the lane renames everything consistently.

Jede Ressource heißt [<namePrefix>-]<subchart>-<laneName>[-<instance>]. Der Komponententyp ist nicht Teil des Namens — der Kind unterscheidet das Deployment ohnehin vom Service namens krypton-payments-release. Mehrere Ressourcen einer Art bekommen eine instance: krypton-payments rendert seine ConfigMaps, Secrets und VaultStaticSecrets aus Maps und nutzt den Map-Key, normalisiert auf ein DNS-1123-Label (camelCase-Grenzen werden zu Bindestrichen, alles wird kleingeschrieben, andere Zeichen werden zu Bindestrichen). global.namePrefix stellt jedem Namen etwas voran, global.partOfPrefix nur dem Lane-Label app.kubernetes.io/part-of. Ein Lane-Wechsel benennt alles konsistent um.

helm template krypton krypton-umbrella-slim --set global.laneName=test
helm template krypton krypton-umbrella-slim --set global.namePrefix=acme
helm template krypton krypton-umbrella-slim --set krypton-payments.configMaps.featureFlags.FF_X=on --set krypton-payments.configMaps.Rate_Limits.RL=1
Guards: an empty or malformed global.laneName fails the umbrella schema (see guardrails); a key that appears in both secrets and vault.secrets would produce two Secrets of one name and is refused by the subchart. Names are truncated to 63 characters.Absicherungen: ein leeres oder ungültiges global.laneName scheitert am Umbrella-Schema (siehe Leitplanken); ein Key, der in secrets und vault.secrets zugleich vorkommt, ergäbe zwei Secrets eines Namens und wird vom Subchart abgelehnt. Namen werden auf 63 Zeichen gekürzt.

Shared resources without the lane

Geteilte Ressourcen ohne Lane

ConfigMaps and Secrets that every lane deployment in a namespace consumes only have to exist once. The krypton-shared subchart renders them with shared: true: the name drops the lane segment (krypton-shared-<key>) and the app.kubernetes.io/part-of label is omitted. Exactly one ArgoCD Application per namespace may own them, so ownership is the plain deploy switch krypton-shared.enabled. Consumers reference the objects with the same helper call plus chart: krypton-shared — the reference can never drift from the rendered name.

ConfigMaps und Secrets, die jedes Lane-Deployment in einem Namespace nutzt, müssen nur einmal existieren. Das Subchart krypton-shared rendert sie mit shared: true: Der Name verliert das Lane-Segment (krypton-shared-<key>), das app.kubernetes.io/part-of-Label entfällt. Genau eine ArgoCD-Application pro Namespace darf sie besitzen, die Eigentümerschaft ist deshalb der gewöhnliche Deploy-Schalter krypton-shared.enabled. Konsumenten referenzieren die Objekte mit demselben Helper-Aufruf plus chart: krypton-shared — die Referenz kann nie vom gerenderten Namen abdriften.

helm template krypton krypton-umbrella-slim
helm template krypton-shared krypton-umbrella-slim -f krypton-umbrella-slim/values-shared-only.yaml
helm template krypton krypton-umbrella-slim --set krypton-shared.enabled=true
Ownership: one Application per namespace enables krypton-shared — the owning lane, or a dedicated shared Application via values-shared-only.yaml (see ArgoCD); every other lane keeps the default. shared: true also works inside an application subchart for a resource all of its lanes consume (krypton-payments-smtp) — then exactly one deployment must create it and the others reference the name only. A configured global.namePrefix is kept on shared names: the prefix separates umbrellas, the lane segment separates lanes.Eigentümerschaft: eine Application pro Namespace aktiviert krypton-shared — die Eigentümer-Lane oder eine eigene shared-Application über values-shared-only.yaml (siehe ArgoCD); jede andere Lane behält den Default. shared: true funktioniert auch innerhalb eines Anwendungs-Subcharts für eine Ressource, die alle seine Lanes konsumieren (krypton-payments-smtp) — dann muss genau ein Deployment sie erzeugen, die anderen referenzieren nur den Namen. Ein konfiguriertes global.namePrefix bleibt auf geteilten Namen erhalten: Das Präfix trennt Umbrellas, das Lane-Segment trennt Lanes.

Labels & annotations: global → subchart → call site

Labels & Annotations: global → Subchart → Aufrufstelle

Chart-generated standard keys merge with the static global.labels / global.annotations, then with the subchart’s own labels: / annotations: block — which the umbrella can fill or override per subchart (krypton-payments.labels, krypton-notifier.annotations) — then with per-call extras. Later wins on key collisions; the two ArgoCD annotations are applied last and can never be shadowed. The generated annotation <labelDomain>/source-chart records which chart version produced the resource.

Chart-generierte Standard-Keys verschmelzen mit den statischen global.labels / global.annotations, dann mit dem eigenen labels:-/annotations:-Block des Subcharts — den das Umbrella je Subchart füllen oder überschreiben kann (krypton-payments.labels, krypton-notifier.annotations) —, dann mit den Extras je Aufruf. Bei Key-Kollisionen gewinnt der spätere; die beiden ArgoCD-Annotations kommen zuletzt und können nie überdeckt werden. Die generierte Annotation <labelDomain>/source-chart hält fest, welche Chart-Version die Ressource erzeugt hat.

Merge order: labels: standard → global.labels → <subchart>.labels → extraLabels. Annotations: standard → global.annotations → <subchart>.annotations → extraAnnotations → annotation → annotationsFrom → sync-wave → sync-options. Values must be strings; the schema rejects anything else in the static maps.Merge-Reihenfolge: Labels: Standard → global.labels → <subchart>.labels → extraLabels. Annotations: Standard → global.annotations → <subchart>.annotations → extraAnnotations → annotation → annotationsFrom → Sync-Wave → Sync-Options. Werte müssen Strings sein; das Schema lehnt alles andere in den statischen Maps ab.

Annotations for exactly one resource

Annotations für genau eine Ressource

The maps above reach every resource. For a single one — the HAProxy timeout of the Route, not of the Deployment next to it — the metadata (or annotations) call takes three optional arguments: extraAnnotations (a dict), annotation (one key=value string) and annotationsFrom (a dotted path below .Values). The path form tolerates a missing path, so inside a range over several Routes only the instances that carry a routes.<name>.annotations block get one; a path that holds anything but a map fails the render. The krypton-payments Route uses the dict form.

Die Maps oben erreichen jede Ressource. Für eine einzelne — das HAProxy-Timeout der Route, nicht des Deployments daneben — nimmt der metadata- (oder annotations-) Aufruf drei optionale Argumente: extraAnnotations (ein Dict), annotation (ein key=value-String) und annotationsFrom (ein Punkt-Pfad unterhalb von .Values). Die Pfad-Form toleriert einen fehlenden Pfad, in einem range über mehrere Routes bekommen also nur die Instanzen mit einem routes.<name>.annotations-Block eine; ein Pfad, der etwas anderes als eine Map enthält, lässt das Rendern fehlschlagen. Die krypton-payments-Route nutzt die Dict-Form.

One mechanism, three spellings: all three merge after the subchart annotations and below the two ArgoCD keys, in the order dict → one-liner → path. Scalar values from a values path are stringified, so a numeric timeout is safe. The full library calls the dict argument extra.Ein Mechanismus, drei Schreibweisen: alle drei werden nach den Subchart-Annotations und unterhalb der beiden ArgoCD-Keys gemergt, in der Reihenfolge Dict → Einzeiler → Pfad. Skalare Werte aus einem Values-Pfad werden stringifiziert, ein numerisches Timeout ist also sicher. Die volle Library nennt das Dict-Argument extra.

Pod selectors: Deployment ↔ Service

Pod-Selektoren: Deployment ↔ Service

selectorLabels is the identity subset that Deployment and Service selectors match pods by: exactly app.kubernetes.io/name, app.kubernetes.io/instance (the Helm release, i.e. the ArgoCD Application) and app.kubernetes.io/part-of (the lane), each carrying the value the pod template receives from labels. The lane is part of the identity so one lane’s Service can never select another lane’s pods in a shared namespace. Pods are never shared, so the selector always carries the lane.

selectorLabels ist die Identitäts-Teilmenge, über die Deployment- und Service-Selektoren Pods finden: genau app.kubernetes.io/name, app.kubernetes.io/instance (das Helm-Release, also die ArgoCD-Application) und app.kubernetes.io/part-of (die Lane), jeweils mit dem Wert, den das Pod-Template aus labels bekommt. Die Lane gehört zur Identität, damit der Service einer Lane in einem geteilten Namespace nie die Pods einer anderen Lane auswählt. Pods sind nie shared, der Selektor trägt die Lane also immer.

helm template krypton krypton-umbrella-slim --set global.partOfPrefix=krypton-umbrella-slim
One-way door: a Deployment selector is immutable. Renaming the lane creates a new Deployment anyway, but changing global.partOfPrefix on a lane that already runs changes only the selector and the apply is rejected — delete that lane’s Deployments once, then sync again. Never add chart version or custom labels to the selector.Einbahnstraße: ein Deployment-Selektor ist unveränderlich. Eine Lane-Umbenennung erzeugt ohnehin ein neues Deployment, aber global.partOfPrefix auf einer bereits laufenden Lane zu ändern verändert nur den Selektor und der Apply wird abgelehnt — die Deployments dieser Lane einmalig löschen, dann erneut syncen. Nie Chart-Version oder eigene Labels in den Selektor aufnehmen.

Sync waves: subchart → umbrella → global

Sync-Waves: Subchart → Umbrella → global

A wave is resolved per component type, first hit wins: the subchart’s syncWaves.<component> (into which Helm has already coalesced the umbrella’s krypton-payments.syncWaves override), then global.syncWaves.<component>. krypton-payments ships route: "2", the umbrella bumps it to "3"; every other component falls back to the platform defaults. Nothing configured anywhere means no annotation at all.

Eine Wave wird pro Komponententyp aufgelöst, der erste Treffer gewinnt: syncWaves.<component> des Subcharts (in das Helm den Umbrella-Override krypton-payments.syncWaves bereits koalesziert hat), dann global.syncWaves.<component>. krypton-payments bringt route: "2" mit, das Umbrella hebt auf "3"; jede andere Komponente fällt auf die Plattform-Defaults zurück. Nirgends konfiguriert heißt: gar keine Annotation.

Why readiness matters: ArgoCD only starts the next wave once the current one is healthy. The demo Deployments carry readiness probes, so wave 3 (the Route) really waits for running pods; without a probe “healthy” would merely mean “container started”.Warum Readiness zählt: ArgoCD startet die nächste Wave erst, wenn die aktuelle healthy ist. Die Demo-Deployments tragen Readiness-Probes, Wave 3 (die Route) wartet also wirklich auf laufende Pods; ohne Probe hieße „healthy“ nur „Container gestartet“.

Cross-subchart ordering with syncWaveOffset

Subchart-übergreifende Reihenfolge mit syncWaveOffset

To sync one subchart entirely after another, shift its band: syncWaveOffset (per subchart, set from the umbrella) is added to every resolved wave. Components without a configured wave — implicitly wave 0 in ArgoCD — are annotated with the bare offset, so they move with the block instead of escaping to wave 0. Keep component waves inside -9..9 and step offsets by 10, then bands never overlap.

Soll ein Subchart vollständig nach einem anderen syncen, verschiebt man sein Band: syncWaveOffset (je Subchart, aus dem Umbrella gesetzt) wird auf jede aufgelöste Wave addiert. Komponenten ohne konfigurierte Wave — in ArgoCD implizit Wave 0 — bekommen den bloßen Offset, sie wandern also mit dem Block statt auf Wave 0 zu entkommen. Komponenten-Waves innerhalb von -9..9 halten und Offsets in Zehnerschritten wählen, dann überlappen sich Bänder nie.

ArgoCD sync options per component

ArgoCD-Sync-Options je Komponente

syncOptions.<component> takes a list of ArgoCD resource-level sync options (a comma-separated string works too) and renders argocd.argoproj.io/sync-options. Same precedence chain as the waves; the first hit replaces, lists never merge — so a subchart switches an inherited platform rule off with []. The platform rule here: never auto-prune Vault-sourced Secrets. krypton-payments additionally keeps its public Route even if the manifest disappears from git or the Application is deleted.

syncOptions.<component> nimmt eine Liste von ArgoCD-Sync-Options auf Ressourcenebene (ein kommagetrennter String geht auch) und rendert argocd.argoproj.io/sync-options. Gleiche Vorrangkette wie bei den Waves; der erste Treffer ersetzt, Listen werden nie gemergt — ein Subchart schaltet eine geerbte Plattform-Regel also mit [] ab. Die Plattform-Regel hier: Vault-basierte Secrets nie automatisch prunen. krypton-payments behält zusätzlich seine öffentliche Route, auch wenn das Manifest aus git verschwindet oder die Application gelöscht wird.

helm template krypton krypton-umbrella-slim --set 'krypton-payments.syncOptions.service=Replace=true\,ServerSideApply=true'
helm template krypton krypton-umbrella-slim -f opt-off.yaml # krypton-payments.syncOptions.vaultStaticSecret: []
Empty list from the CLI: --set ...vaultStaticSecret=[] arrives as the string "[]" and fails the schema; use a values file (as above) or --set-json. The schema also checks each entry against Name=value.Leere Liste von der CLI: --set ...vaultStaticSecret=[] kommt als String "[]" an und scheitert am Schema; eine Values-Datei (wie oben) oder --set-json nehmen. Das Schema prüft zudem jeden Eintrag gegen Name=value.

Deploy switches per subchart

Deploy-Schalter je Subchart

Every application subchart is guarded by a condition: in the umbrella Chart.yaml and switched from the umbrella values. A missing flag would count as enabled, so the flags are set explicitly and every lane can flip them. The library itself is unconditional: disabling it would drop the helper templates from the render namespace and break every enabled subchart.

Jedes Anwendungs-Subchart hängt an einer condition: in der Umbrella-Chart.yaml und wird aus den Umbrella-Values geschaltet. Ein fehlendes Flag zählte als aktiviert, die Flags sind deshalb explizit gesetzt und jede Lane kann sie umlegen. Die Library selbst ist unbedingt: Sie abzuschalten würde die Helper-Templates aus dem Render-Namensraum entfernen und jedes aktivierte Subchart brechen.

helm template krypton krypton-umbrella-slim --set krypton-payments.enabled=false

VaultStaticSecrets: instances & lane-aware paths

VaultStaticSecrets: Instanzen & Lane-abhängige Pfade

One VaultStaticSecret per vault.secrets entry, the key as instance. The CRD writes a Secret of the same name (destination.name is computed with the identical helper call the Deployment uses for its secretRef), so the two can never disagree. Paths go through tpl in the subchart template — the library deliberately has no tpl helper, the spec is the subchart’s business — so the defaults template the lane in and every lane reads its own secrets. The type-level wave -1 and the platform rule Prune=false apply to every instance.

Ein VaultStaticSecret je vault.secrets-Eintrag, der Key als Instanz. Die CRD schreibt ein Secret desselben Namens (destination.name entsteht mit dem identischen Helper-Aufruf, den das Deployment für sein secretRef nutzt), die beiden können sich also nie widersprechen. Pfade laufen im Subchart-Template durch tpl — die Library hat bewusst keinen tpl-Helper, die Spec ist Sache des Subcharts —, die Defaults templaten also die Lane hinein und jede Lane liest ihre eigenen Secrets. Die Typ-Wave -1 und die Plattform-Regel Prune=false gelten für jede Instanz.

Guard: a key present in both secrets and vault.secrets would make two Secrets fight over one name — the subchart refuses the render (see guardrails). krypton-shared renders its Vault secrets the same way, minus the lane in name and path.Absicherung: ein Key, der in secrets und vault.secrets zugleich vorkommt, ließe zwei Secrets um einen Namen streiten — das Subchart verweigert das Rendern (siehe Leitplanken). krypton-shared rendert seine Vault-Secrets genauso, nur ohne Lane in Name und Pfad.

Rebranding the label domain

Label-Domain umbenennen

The only key the library generates under a domain is <labelDomain>/source-chart; global.labelDomain renames that prefix without touching the library. The static entries under global.labels / global.annotations are plain values and are edited alongside when rebranding.

Der einzige Key, den die Library unter einer Domain erzeugt, ist <labelDomain>/source-chart; global.labelDomain benennt dieses Präfix um, ohne die Library anzufassen. Die statischen Einträge unter global.labels / global.annotations sind einfache Werte und werden beim Rebranding mit angepasst.

helm template krypton krypton-umbrella-slim --set global.labelDomain=acme.io

Die schlanke Variante bringt keine Subchart-Schemas mit — ein Subchart bekommt eines, wenn seine eigenen Keys validiert werden sollen.

Guardrails

Leitplanken

Misconfiguration never degrades silently. The umbrella schema validates global and the library-relevant keys of every subchart block; the component catalog validates every component key at render time; the subcharts refuse name collisions they can foresee.

Fehlkonfiguration degradiert nie still. Das Umbrella-Schema validiert global und die Library-relevanten Keys jedes Subchart-Blocks; der Komponentenkatalog validiert jeden Komponenten-Key beim Rendern; die Subcharts verweigern Namenskollisionen, die sie vorhersehen können.

helm template krypton krypton-umbrella-slim --set krypton-payments.syncWaves.rout=9
helm template krypton krypton-umbrella-slim --set krypton-notifier.syncWaveOffset=abc
helm template krypton krypton-umbrella-slim --set global.lane=test
helm template krypton krypton-umbrella-slim --set global.laneName=
helm template krypton krypton-umbrella-slim --set krypton-payments.secrets.app.X=1
Not guarded on purpose: keys outside the typed set in a subchart block pass through untyped — a typo in replicaCount reaches the subchart as written. Add a values.schema.json to a subchart when its own keys should be validated too.Bewusst nicht abgesichert: Keys außerhalb der typisierten Menge in einem Subchart-Block werden untypisiert durchgereicht — ein Tippfehler in replicaCount erreicht das Subchart wie geschrieben. Ein Subchart bekommt eine eigene values.schema.json, wenn auch seine eigenen Keys validiert werden sollen.
GitOps

ArgoCD

Point one Application per lane at krypton-umbrella-slim; waves order resources within each sync, the lane is set via a Helm parameter or a values file. Lane Applications leave krypton-shared.enabled at its default (off) and merely reference the shared objects; one additional Application per namespace owns them through values-shared-only.yaml. The slim umbrella is excluded from the full chart via .helmignore and deployed as its own Application.

Pro Lane zeigt eine Application auf krypton-umbrella-slim; die Waves ordnen die Ressourcen innerhalb jedes Syncs, die Lane kommt aus einem Helm-Parameter oder einer Values-Datei. Lane-Applications lassen krypton-shared.enabled auf dem Default (aus) und referenzieren die geteilten Objekte nur; eine zusätzliche Application pro Namespace besitzt sie über values-shared-only.yaml. Das schlanke Umbrella ist per .helmignore aus dem vollen Chart ausgenommen und wird als eigene Application deployt.

Dependency build: ArgoCD runs helm dependency build before templating a git-sourced chart; with repository-less directory dependencies that step only prints “Assuming it exists in the charts directory” per entry and leaves the directory charts in place. No Chart.lock is committed on purpose — a stale one would make that step fail with “Chart.lock is out of sync”.Dependency-Build: ArgoCD führt vor dem Templating eines git-basierten Charts helm dependency build aus; bei Verzeichnis-Abhängigkeiten ohne Repository gibt dieser Schritt nur „Assuming it exists in the charts directory“ je Eintrag aus und lässt die Verzeichnis-Charts unangetastet. Bewusst wird kein Chart.lock committet — ein veraltetes ließe diesen Schritt mit „Chart.lock is out of sync“ fehlschlagen.
