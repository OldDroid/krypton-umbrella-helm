krypton-umbrella-slim

This independent umbrella uses the smaller krypton-lib-slim library for names, labels, annotations and Argo CD settings. It also provides selector labels and name validation. Workload settings remain in subchart templates.

Dieses eigenständige Umbrella verwendet die kleinere Library krypton-lib-slim. Sie erzeugt Namen, Labels und Annotations mit Argo-CD-Einstellungen und stellt Selektorlabels sowie eine Namensprüfung bereit. Workload-Einstellungen bleiben in den Templates der Subcharts.

Library validation: resource names longer than 63 characters or with an invalid format fail rendering. The combined partOfPrefix/laneName label must also fit within 63 characters. Existing configurations that relied on name truncation need an explicit migration. Decimal wave strings such as "08" mean 8; invalid integers and signed 64-bit overflow are rejected. Quote padded and very large numbers in YAML. The dedicated library references are in krypton-umbrella-slim/charts/krypton-lib-slim/README.md and README.de.md.Library-Prüfungen: Ressourcennamen mit mehr als 63 Zeichen oder ungültigem Format führen zum Fehler. Das zusammengesetzte Label aus partOfPrefix/laneName darf ebenfalls höchstens 63 Zeichen lang sein. Bisher gekürzte Namen benötigen eine geplante Migration. Dezimale Wave-Strings wie "08" ergeben 8; ungültige Ganzzahlen und 64-Bit-Überläufe werden abgelehnt. Zahlen mit führenden Nullen und sehr große Zahlen in YAML als Strings angeben. Die eigenen Library-Referenzen stehen in krypton-umbrella-slim/charts/krypton-lib-slim/README.md und README.de.md.

Overview

Überblick

Subcharts use krypton-lib-slim as a local dependency, loaded directly when the umbrella renders. Slim keeps workload templates with application teams. Both variants use the same naming scheme and component catalog; different subchart names still produce different resource names.

Die Subcharts liegen unter charts/ und verwenden krypton-lib-slim als lokale Abhängigkeit. Beim Rendern des Umbrellas lädt Helm die gemeinsame Library direkt. Slim eignet sich für Teams, die ihre Workload-Templates selbst pflegen. Beide Varianten verwenden dasselbe Namensschema und dieselben Komponententypen; unterschiedliche Subchart-Namen ergeben natürlich unterschiedliche Ressourcennamen.

Seven helpers, one dict each: metadata (the whole block), componentName (names and cross-references), labels, selectorLabels, annotations, syncWave, syncOptions. ctx is always the caller’s root context — . in a template, $ or a saved $root inside a range. Arguments and values are listed in the reference.Sieben Helper, je ein Dict: metadata (der ganze Block), componentName (Namen und Querverweise), labels, selectorLabels, annotations, syncWave, syncOptions. ctx ist immer der Root-Kontext des Aufrufers — . im Template, $ oder ein gesichertes $root in einem range. Argumente und Values stehen in der Referenz.

Getting started

Einstieg

Run these commands from the repository root. Rendering produces YAML without installing it. Standalone subcharts need their library dependency built first. Gitignored library copies can still be loaded by Helm; remove stale copies before umbrella tests or use a fresh checkout.

Die Befehle gelten ab dem Stammverzeichnis dieses Repositorys. helm template erzeugt YAML, installiert aber nichts. Für ein einzelnes Subchart muss zuerst seine Library-Abhängigkeit gebaut werden. Erzeugte Library-Kopien können trotz .gitignore später von Helm geladen werden; vor Umbrella-Tests alte Kopien entfernen oder eine frische Arbeitskopie verwenden.

Configuration examples

Konfigurationsbeispiele

Each card pairs configuration with illustrative YAML excerpts. Comments and omissions explain the relevant parts. Run the command with the shown overrides for complete output.

One include for the whole metadata block

Ein Include für den ganzen Metadata-Block

The core use-case. A manifest calls krypton-lib-slim.metadata once and receives name:, labels: and annotations:; everything else in the file is the subchart’s own YAML. The same names are reused for cross-references through componentName — the ServiceAccount the pod runs as, the ConfigMaps and Secrets it consumes — so a reference can never drift from the resource it points at.

Ein Aufruf von krypton-lib-slim.metadata erzeugt name, labels und annotations. Das restliche Manifest bleibt im Subchart. Referenzen verwenden componentName mit denselben Argumenten, damit die Namen übereinstimmen.

Inside a range: the library needs the root context, not the loop item — pass $ (or a $root := . saved before the loop) as ctx, as the envFrom loops above do.In einem range: die Library braucht den Root-Kontext, nicht das Schleifenelement — $ (oder ein vor der Schleife gesichertes $root := .) als ctx übergeben, wie die envFrom-Schleifen oben.

Names, lanes & instance identifiers

Namen, Lanes & Instanz-Bezeichner

Every resource is named [<namePrefix>-]<subchart>-<laneName>[-<instance>]. The component type is not part of the name — the kind already tells the Deployment from the Service called krypton-payments-release. Several resources of one kind get an instance: krypton-payments renders its ConfigMaps, Secrets and VaultStaticSecrets from maps and uses the map key, normalised to a DNS-1123 label (camelCase boundaries become dashes, everything is lowercased, other characters become dashes). global.namePrefix prefixes every name, global.partOfPrefix prefixes only the app.kubernetes.io/part-of lane label. Switching the lane renames everything consistently.

Eine Lane ist eine Umgebung wie release oder test. Namen folgen dem Schema [<namePrefix>-]<subchart>-<lane>[-<instance>]. Deployment und Service dürfen gleich heißen, weil ihre Ressourcentypen verschieden sind. Mehrere Ressourcen desselben Typs brauchen unterschiedliche Instanzen. Namen mit mehr als 63 Zeichen oder ungültigem Format führen zu einer Fehlermeldung. namePrefix betrifft Namen; partOfPrefix betrifft nur das Lane-Label. Ein Lane-Wechsel ändert nicht automatisch Ressourcenlimits oder Replikazahlen.

helm template krypton krypton-umbrella-slim --set global.laneName=test
helm template krypton krypton-umbrella-slim --set global.namePrefix=acme
helm template krypton krypton-umbrella-slim --set krypton-payments.configMaps.featureFlags.FF_X=on --set krypton-payments.configMaps.Rate_Limits.RL=1
Guards: an empty or malformed global.laneName fails the umbrella schema (see guardrails); a key that appears in both secrets and vault.secrets would produce two Secrets of one name and is refused by the subchart. Names longer than 63 characters or with an invalid format fail rendering.Absicherungen: ein leeres oder ungültiges global.laneName scheitert am Umbrella-Schema (siehe Validierung); ein Key, der in secrets und vault.secrets zugleich vorkommt, ergäbe zwei Secrets eines Namens und wird vom Subchart abgelehnt. Namen mit mehr als 63 Zeichen oder ungültigem Format werden abgelehnt.

Shared resources without the lane

Geteilte Ressourcen ohne Lane

ConfigMaps and Secrets that every lane deployment in a namespace consumes only have to exist once. The krypton-shared subchart renders them with shared: true: the name drops the lane segment (krypton-shared-<key>) and the app.kubernetes.io/part-of label is omitted. Exactly one ArgoCD Application per namespace may own them, so ownership is the plain deploy switch krypton-shared.enabled. Consumers reference the objects with the same helper call plus chart: krypton-shared — the reference can never drift from the rendered name.

Gemeinsame ConfigMaps und Secrets werden von krypton-shared mit shared: true erzeugt. Dadurch entfallen Lane-Segment und Lane-Label. Pro Ressourcennamen ist genau ein Bereitsteller zuständig. Andere Applications referenzieren das Objekt über chart: krypton-shared; benötigte Objekte müssen vorher vorhanden sein.

helm template krypton krypton-umbrella-slim
helm template krypton-shared krypton-umbrella-slim -f krypton-umbrella-slim/values-shared-only.yaml
helm template krypton krypton-umbrella-slim --set krypton-shared.enabled=true
Ownership: one Application per namespace enables krypton-shared — the owning lane, or a dedicated shared Application via values-shared-only.yaml (see ArgoCD); every other lane keeps the default. shared: true also works inside an application subchart for a resource all of its lanes consume (krypton-payments-smtp) — then exactly one deployment must create it and the others reference the name only. A configured global.namePrefix is kept on shared names: the prefix separates umbrellas, the lane segment separates lanes.Eigentümerschaft: eine Application pro Namespace aktiviert krypton-shared — die Eigentümer-Lane oder eine eigene shared-Application über values-shared-only.yaml (siehe ArgoCD); jede andere Lane behält den Default. shared: true funktioniert auch innerhalb eines Anwendungs-Subcharts für eine Ressource, die alle seine Lanes konsumieren (krypton-payments-smtp) — dann muss genau ein Deployment sie erzeugen, die anderen referenzieren nur den Namen. Ein konfiguriertes global.namePrefix bleibt auf geteilten Namen erhalten: Das Präfix trennt Umbrellas, das Lane-Segment trennt Lanes.

Labels & annotations: global → subchart → call site

Labels & Annotations: global → Subchart → Aufrufstelle

Labels merge globals, subchart labels and per-call extras, then the library applies reserved Pod identity labels. Annotations follow the same layers with optional single values and values paths. Configured Argo CD values take precedence; all resulting values are strings.

Eigene Labels werden in der Reihenfolge global.labels → Subchart-labels → extraLabels zusammengeführt. Anschließend setzt die Library die reservierten Pod-Identitätslabels. Annotations folgen derselben Ebenenfolge, ergänzt um Einzelwert und Values-Pfad. Konfigurierte Argo-CD-Werte haben Vorrang; alle Werte werden als Strings ausgegeben.

Merge order: labels: standard → global.labels → <subchart>.labels → extraLabels. Annotations: standard → global.annotations → <subchart>.annotations → extraAnnotations → annotation → annotationsFrom → sync-wave → sync-options. Values must be strings; the schema rejects anything else in the static maps.Merge-Reihenfolge: Labels: Standard → global.labels → <subchart>.labels → extraLabels. Annotations: Standard → global.annotations → <subchart>.annotations → extraAnnotations → annotation → annotationsFrom → Sync-Wave → Sync-Options. Werte müssen Strings sein; das Schema lehnt alles andere in den statischen Maps ab.

Annotations for exactly one resource

Annotations für genau eine Ressource

The maps above reach every resource. For a single one — the HAProxy timeout of the Route, not of the Deployment next to it — the metadata (or annotations) call takes three optional arguments: extraAnnotations (a dict), annotation (one key=value string) and annotationsFrom (a dotted path below .Values). The path form tolerates a missing path, so inside a range over several Routes only the instances that carry a routes.<name>.annotations block get one; a path that holds anything but a map fails the render. The krypton-payments Route uses the dict form.

Für Annotations einer einzelnen Ressource stehen extraAnnotations als Map, annotation als String key=value und annotationsFrom als Punktpfad unter .Values bereit. Ein fehlender Pfad wird ignoriert; ein vorhandener skalarer Zielwert lässt das Rendern fehlschlagen. Payments reicht die Route-Annotations als Map weiter.

One mechanism, three spellings: all three merge after the subchart annotations and below the two ArgoCD keys, in the order dict → one-liner → path. Scalar values from a values path are stringified, so a numeric timeout is safe. The full library calls the dict argument extra.Ein Mechanismus, drei Schreibweisen: alle drei werden nach den Subchart-Annotations und unterhalb der beiden ArgoCD-Keys gemergt, in der Reihenfolge Dict → Einzeiler → Pfad. Skalare Werte aus einem Values-Pfad werden stringifiziert, ein numerisches Timeout ist also sicher. Die volle Library nennt das Dict-Argument extra.

Pod selectors: Deployment ↔ Service

Pod-Selektoren: Deployment ↔ Service

Selectors use the same three reserved identity labels as Pod templates. The instance label is the Helm release name, which defaults to the Argo CD Application name unless helm.releaseName overrides it. Deployment selectors are immutable.

Deployment- und Service-Selektoren verwenden die Labels app.kubernetes.io/name, app.kubernetes.io/instance und app.kubernetes.io/part-of. Die Library setzt diese Werte auch am Pod-Template und schützt sie vor Überschreiben. Der Release-Name ist standardmäßig der Argo-CD-Application-Name, kann aber mit helm.releaseName abweichen. Deployment-Selektoren sind unveränderlich; Änderungen am Lane-Label benötigen eine geplante Neuerstellung.

helm template krypton krypton-umbrella-slim --set global.partOfPrefix=krypton-umbrella-slim
Selector changes: a Deployment selector is immutable. Renaming the lane creates a new Deployment anyway, but changing global.partOfPrefix on a lane that already runs changes only the selector and the apply is rejected — plan recreation of affected Deployments and account for possible downtime. Never add chart version or custom labels to the selector.Selektoränderungen: ein Deployment-Selektor ist unveränderlich. Eine Lane-Umbenennung erzeugt ohnehin ein neues Deployment, aber global.partOfPrefix auf einer bereits laufenden Lane zu ändern verändert nur den Selektor und der Apply wird abgelehnt — die Neuerstellung betroffener Deployments planen und mögliche Ausfallzeiten berücksichtigen. Nie Chart-Version oder eigene Labels in den Selektor aufnehmen.

Sync waves: subchart values (with umbrella overrides) → global

Sync-Waves: Subchart-Werte (mit Umbrella-Overrides) → global

Subchart waves, including umbrella overrides, take precedence over global waves. Without a wave or offset no wave annotation is generated.

Für eine Komponente gilt zuerst syncWaves.<component> im Subchart einschließlich Umbrella-Overrides, danach global.syncWaves.<component>. Ohne Wave und ohne Offset wird keine Wave-Annotation erzeugt. Die Zahl 0 und negative Zahlen sind gültig; YAML-null ist kein Zahlenwert.

Why readiness matters: ArgoCD only starts the next wave once the current one is healthy. The demo Deployments carry readiness probes, so wave 3 (the Route) really waits for running pods; without a probe “healthy” would merely mean “container started”.Warum Readiness zählt: ArgoCD startet die nächste Wave erst, wenn die aktuelle healthy ist. Die Demo-Deployments tragen Readiness-Probes, Wave 3 (die Route) wartet also wirklich auf laufende Pods; ohne Probe hieße „healthy“ nur „Container gestartet“.

Cross-subchart ordering with syncWaveOffset

Subchart-übergreifende Reihenfolge mit syncWaveOffset

syncWaveOffset shifts all component waves, using zero as the base for unconfigured types. Choose offsets using actual ranges. Local waves -9..9 require a step of at least 19 to avoid overlap.

syncWaveOffset verschiebt alle Waves des Subcharts um denselben Wert. Eine nicht konfigurierte Wave zählt dafür als null. Die tatsächlichen Bereiche müssen getrennt bleiben: Für lokale Waves -9..9 sind mindestens 19 Abstand nötig; Zehnerschritte würden überlappen.

ArgoCD sync options per component

ArgoCD-Sync-Options je Komponente

syncOptions.<component> takes a list of ArgoCD resource-level sync options (a comma-separated string works too) and renders argocd.argoproj.io/sync-options. Same precedence chain as the waves; the first hit replaces, lists never merge — so a subchart switches an inherited platform rule off with []. The platform rule here: never auto-prune Vault-sourced Secrets. krypton-payments additionally keeps its public Route even if the manifest disappears from git or the Application is deleted.

syncOptions.<component> akzeptiert eine Liste oder einen kommagetrennten String. Der Subchart-Wert ersetzt den globalen vollständig; [] hebt eine geerbte Liste auf. Prune=false schützt beim Sync-Pruning, Delete=false zusätzlich bei kaskadierender Application-Löschung. Payments verwendet beide Optionen für seine Route.

helm template krypton krypton-umbrella-slim --set 'krypton-payments.syncOptions.service=Replace=true\,ServerSideApply=true'
helm template krypton krypton-umbrella-slim -f opt-off.yaml # krypton-payments.syncOptions.vaultStaticSecret: []
Empty list from the CLI: --set ...vaultStaticSecret=[] arrives as the string "[]" and fails the schema; use a values file (as above) or --set-json. The schema also checks each entry against Name=value.Leere Liste von der CLI: --set ...vaultStaticSecret=[] kommt als String "[]" an und scheitert am Schema; eine Values-Datei (wie oben) oder --set-json nehmen. Das Schema prüft zudem jeden Eintrag gegen Name=value.

Deploy switches per subchart

Deploy-Schalter je Subchart

Every application subchart is guarded by a condition: in the umbrella Chart.yaml and switched from the umbrella values. A missing flag would count as enabled, so the flags are set explicitly and every lane can flip them. The library itself is unconditional: disabling it would drop the helper templates from the render namespace and break every enabled subchart.

Ein condition-Eintrag in der Umbrella-Chart.yaml verbindet jedes Subchart mit seinem enabled-Schalter. Bei false werden seine Manifeste nicht mehr erzeugt. Wenn Pruning aktiviert ist, entfernt Argo CD die bisherigen Ressourcen mit Ausnahme geschützter Objekte.

helm template krypton krypton-umbrella-slim --set krypton-payments.enabled=false

VaultStaticSecrets: instances & lane-aware paths

VaultStaticSecrets: Instanzen & Lane-abhängige Pfade

One VaultStaticSecret per vault.secrets entry, the key as instance. The CRD writes a Secret of the same name (destination.name is computed with the identical helper call the Deployment uses for its secretRef), so the two can never disagree. Paths go through tpl in the subchart template — the library deliberately has no tpl helper, the spec is the subchart’s business — so the defaults template the lane in and every lane reads its own secrets. The type-level wave -1 and the platform rule Prune=false apply to every instance.

Payments erzeugt je Eintrag in vault.secrets ein VaultStaticSecret. Das Ziel-Secret und die Deployment-Referenz verwenden denselben Namens-Helper. tpl wertet die Pfade im Subchart-Kontext aus. Die Standardpfade enthalten die Lane; eigene Pfade können davon abweichen. Die Wave und Sync-Options gelten für alle Instanzen dieses Typs.

Guard: a key present in both secrets and vault.secrets would make two Secrets fight over one name — the subchart refuses the render (see guardrails). krypton-shared renders its Vault secrets the same way, minus the lane in name and path.Absicherung: ein Key, der in secrets und vault.secrets zugleich vorkommt, ließe zwei Secrets um einen Namen streiten — das Subchart verweigert das Rendern (siehe Validierung). krypton-shared rendert seine Vault-Secrets genauso, nur ohne Lane in Name und Pfad.

Rebranding the label domain

Label-Domain umbenennen

The only key the library generates under a domain is <labelDomain>/source-chart; global.labelDomain renames that prefix without touching the library. The static entries under global.labels / global.annotations are plain values and are edited alongside when rebranding.

global.labelDomain bestimmt das Präfix der erzeugten Annotation <domain>/source-chart. Eigene Schlüssel unter global.labels und global.annotations müssen bei einem Domain-Wechsel separat angepasst werden.

helm template krypton krypton-umbrella-slim --set global.labelDomain=acme.io

Component catalog

Komponentenkatalog

The single source of truth for component arguments and syncWaves / syncOptions keys (krypton-lib-slim.componentCatalog in _helpers.tpl). An unknown string fails the render with this list in the message; a genuinely new kind is one added line. Configuring a catalogued type that a subchart does not (yet) render is allowed and has no effect.

Der Komponentenkatalog legt die zulässigen Typnamen fest. Neue Typen müssen in beiden Library-Katalogen ergänzt werden. Die Kürzel dienen nur der Dokumentation und erscheinen nicht in Ressourcennamen. Ein bekannter, aber nicht gerenderter Typ hat keine Wirkung.

Guardrails

Validierung

The umbrella schema validates global and library-related values. Slim subcharts have no schemas of their own, so other workload values are not automatically validated. Payments and Shared reject final resource-map names that collide after normalization.

Das Umbrella-Schema prüft globale und Library-bezogene Werte. Slim-Subcharts haben keine eigenen Schemas; andere Workload-Werte sind daher nicht automatisch validiert. Payments und Shared prüfen die fertigen Namen ihrer Ressourcen-Maps auf Normalisierungskollisionen.

helm template krypton krypton-umbrella-slim --set krypton-payments.secrets.app.X=1
Not guarded on purpose: keys outside the typed set in a subchart block pass through untyped — a typo in replicaCount reaches the subchart as written. Add a values.schema.json to a subchart when its own keys should be validated too.Bewusst nicht abgesichert: Keys außerhalb der typisierten Menge in einem Subchart-Block werden untypisiert durchgereicht — ein Tippfehler in replicaCount erreicht das Subchart wie geschrieben. Ein Subchart bekommt eine eigene values.schema.json, wenn auch seine eigenen Keys validiert werden sollen.
GitOps

ArgoCD

Point one Application per lane at krypton-umbrella-slim; waves order resources within each sync, the lane is set via a Helm parameter or a values file. Lane Applications leave krypton-shared.enabled at its default (off) and merely reference the shared objects; one additional Application per namespace owns them through values-shared-only.yaml. The slim umbrella is excluded from the full chart via .helmignore and deployed as its own Application.

Slim wird als eigene Application mit path: krypton-umbrella-slim bereitgestellt. Konsumenten lassen krypton-shared.enabled ausgeschaltet. Eine zuständige Application kann gemeinsame Objekte mit values-shared-only.yaml erzeugen. Diese müssen vor den konsumierenden Anwendungen bereitstehen.

Dependencies: Umbrella dependencies are checked-in directories. Standalone subchart builds create library copies; keep these current or remove them before umbrella tests. Verify rendering with the Helm version used by your Argo CD installation.Abhängigkeiten: Die Umbrella-Abhängigkeiten liegen als Verzeichnisse im Repository. Ein einzelner Subchart-Build erzeugt zusätzliche Library-Kopien. Diese aktuell halten oder vor Umbrella-Tests entfernen. Das Rendern auch mit der Helm-Version der Argo-CD-Installation prüfen.
